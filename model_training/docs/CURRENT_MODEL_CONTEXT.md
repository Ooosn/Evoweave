# Evoweave 模型研究现状

更新：2026-10-24。本文只记录当前问题、已测结果和研究判断；具体运行权限见
[机器状态](../state/current.json)，数据定义见[数据源](../../DATASET_SOURCE_OF_TRUTH.md)。

## 研究问题

从同一资产的多姿态表面观测中恢复完整骨架：运动信息能否帮助区分几何歧义，
同时保留未活动部位，并在未见过的骨架拓扑上泛化。评价同时考虑骨架结构、
关节位置、关节数量和自由生成是否正常结束。

## 当前任务

优先验证“真实帧 ID+XYZ 自回归 + 跨帧结构一致性”。输入仅包含动态 2..24
个真实帧，取消虚拟 query、虚实帧融合和独立辅助骨架头。每帧最终 1,024 个
mesh tokens 条件化同一个完整自回归解码器，在一条序列中生成显式 DFS ID
和 XYZ。每个真实帧都接受 GT token 交叉熵监督，跨帧一致性只作用于 GT 定义
的结构位置，不作用于坐标位置。详见[实验协议](ID_XYZ_CONSISTENCY_20261024.md)。

固定 5,000 资产、原始 root-RT 与归一化不变；先运行 20,000 次资产曝光，
即名义 4 遍数据。配套同模型、相同初始化与抽样的 λ=0 对照；先运行 λ=1，
阶段末分析结果，不自动延长至 100k。当前正在做实现和启动前验证，尚无此
模型的质量结论。

已有原始单 query 基线的恢复比较暂缓。原始入口 `train_dynamic_rig.py`、七月
HGC 与十月十日动态帧训练证据保留在[原始基线](BASELINE_FLAT_UNIRIG.md)。
bestB 是有虚拟帧的历史质量参照，不是本次模型或原始基线的别名。

## 方法与数据

- 原始方法：真实 query 对齐的 1,024 anchor tokens，经空间/时间编码后，
  条件化完整 UniRig 自回归骨架序列；每次资产访问只监督 query 帧。query 是
  真实输入帧之一，老模型没有额外的虚拟 query 帧。
- A/B/C 的关键架构变化是新增一个无真实输入网格的虚拟 query 帧，含 1,024
  slots，再比较虚拟帧与真实帧的融合方式。三组都有虚拟帧；B 使用真实帧作
  attention query、虚拟帧作 key/value，仍属于新架构。多目标监督是另一项变化。
- 当前完整数据：18,002 训练 / 967 验证资产。固定 5k 是其中的实验子集，
  不是另一个数据版本；清单 SHA-256 为
  `a17b6be96fb33a32a1bee7117b07789da6261c6b5693104f3d2cce07c09bab88`。
- 预处理：完整读取 manifest 的 `root_rt`，去除根刚性运动，保留非刚性残差；
  在实际选中输入网格的联合 bbox 上统一中心与尺度，padding 为 1.1。
- 历史七月及十月十日训练使用 15,920 / 856 旧清单，和当前数据分开解释。

协议比较。valid-common60 是分层面板，不是全部验证集或总体分布的无偏估计。

## 已形成的研究判断

1. 模型确实使用几何和姿态条件；主要问题不等于完全忽略输入。
2. 高频骨架族的成功不能代表长尾泛化；关节数、拓扑频率和姿态需分开分析。
3. flat UniRig 的部分生成会在错误前缀下进入重复循环；强行结束不改善骨架本身。
4. 结构和坐标拆开预测具有可训练性，但现有证据尚未证明它提高了最终质量上限。
5. 后续比较需要固定资产、原始帧、GT、失败计分和曝光预算，再解释架构差异。
