# Evoweave 模型研究现状

更新：2026-10-24。本文只记录当前问题、已测结果和研究判断；具体运行权限见
[机器状态](../state/current.json)，数据定义见[数据源](../../DATASET_SOURCE_OF_TRUTH.md)。

## 研究问题

从同一资产的多姿态表面观测中恢复完整骨架：运动信息能否帮助区分几何歧义，
同时保留未活动部位，并在未见过的骨架拓扑上泛化。评价同时考虑骨架结构、
关节位置、关节数量和自由生成是否正常结束。

## 当前任务

复用已经存在的真实 query、单 target 训练实现，在固定 5,000 资产上从官方
初始化重新训练，使用动态 2..24 帧、现有全局 root-RT 对齐和选定输入网格的
统一归一化。双 H100，累计 100,000 次资产曝光，即名义 20 遍数据；一次曝光
只监督一个 query 骨架，不是对全部输入帧分别解码，也不是 100,000 次参数更新。

**已确定：** 原始入口是 `train_dynamic_rig.py`，从 Westlake 延续到七月 HGC
基线；十月十日的动态帧 bias_h8 完整训练也已找到。模型身份、代码、配方和
历史证据见[原始基线](BASELINE_FLAT_UNIRIG.md)。

**待衔接：** 对应“动态帧 + 去全局 RT + 扩展数据”成功运行的完整记录仍待定位；
目前分别确认了动态帧完整训练和 RT 数据接入。接下来把恢复训练的准确配置
绑定到这条已有实现。所请求的 100k 正式训练尚未启动。

## 方法与数据

- 原始方法：真实 query 对齐的 1,024 anchor tokens，经空间/时间编码后，
  条件化完整 UniRig 自回归骨架序列；每次资产访问只监督 query 帧。
- 当前完整数据：18,002 训练 / 967 验证资产。固定 5k 是其中的实验子集，
  不是另一个数据版本；清单 SHA-256 为
  `a17b6be96fb33a32a1bee7117b07789da6261c6b5693104f3d2cce07c09bab88`。
- 预处理：完整读取 manifest 的 `root_rt`，去除根刚性运动，保留非刚性残差；
  在实际选中输入网格的联合 bbox 上统一中心与尺度，padding 为 1.1。
- 历史七月及十月十日训练使用 15,920 / 856 旧清单，和当前数据分开解释。

协议比较。valid-common60 是分层面板，不是全部验证集或总体分布的无偏估计。

## 已形成的研究判断

1. 模型确实使用几何和姿态条件；主要问题不等于完全忽略输入。
2. 高频骨架族的成功不能代表长尾泛化；关节数、拓扑频率和姿态需分开分析。
3. flat UniRig 的部分生成会在错误前缀下进入重复循环；强行结束不改善骨架本身。
4. 结构和坐标拆开预测具有可训练性，但现有证据尚未证明它提高了最终质量上限。
5. 后续比较需要固定资产、原始帧、GT、失败计分和曝光预算，再解释架构差异。
