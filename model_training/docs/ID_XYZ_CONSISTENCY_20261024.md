# 真实帧 ID/XYZ 与结构一致性

## 问题与模型

同一资产不同姿态应具有相同骨架结构，但关节坐标应随姿态变化。本实验检查
显式关节身份和教师强制下的跨帧结构约束是否改善自由生成的一致性与质量。

输入只有 2..24 个真实帧。共享表面编码器提取每帧 1,024 个对应 anchor tokens，
空间/时间编码器保留 96 个 register。每帧最终的 1,024 个 mesh tokens 输入
同一个完整 UniRig/OPT 自回归解码器。无虚拟 query、虚实帧融合、独立结构
辅助头或单独 XYZ 填空解码器。所有真实帧参与监督。

表面编码器、投影及完整自回归主干来自官方 checkpoint。旧词表的输入嵌入
和输出头逐行保留，只追加 256 个关节 ID；新增 ID 与运动模块分别使用固定
种子初始化。不载入任何历史实验训练权重。

## 序列与损失

序列为 `BOS CLS J0 x y z J1 x y z ... BRANCH parentID newID x y z ... EOS`。
父关节引用只使用 ID，不重复其坐标；ID 按原始索引稳定 DFS 次序编号，因此
原始父子关系不受坐标量化碰撞影响。坐标仍使用官方 [-1,1]、256 bins 协议。
256 关节最坏完整序列长度为 1,535 tokens，加 1,024 条件 tokens 后在解码器
3,076 个位置之内。该容量是语法上限，不代表实际数据最长序列。

一次因果教师强制前向同时预测所有下一个 token。主损失是完整序列 GT CE，
先在各帧有效 token 上平均，再平均帧和资产。PAD 不计分。

一致性只选择 GT 的新 ID、父 ID、BRANCH 与 EOS 位置。对帧 t，用其他真实帧
在同位置的完整词表概率均值作为停止梯度的软目标，计算交叉熵；每帧轮流作为
被监督方，平均结构位置、帧和资产。无自由 rollout 对齐，也不对 argmax 求导。
总损失为 `main_CE + lambda * consistency_CE`，温度为 1。

一致性 CE 包含目标分布熵，故分布已经相同时数值不必为零。另报扣除目标熵
后的 KL 诊断值来表示分布分歧；训练目标仍是 CE，不把两者混称。

## 对照与预算

保持固定 5k 训练 / 967 验证清单、完整 root-RT 描述、选中输入网格联合 bbox
归一化与每资产 8 个留出姿态。无关节裁剪、坐标 clipping 或额外全局旋转。

用户将 λ=1 的总预算明确增加为 100,000 次资产曝光，即 5k 子集约 20 遍。
已完成的前 5,000 次曝光和 105 次更新保持不变，从完整断点恢复模型、Adam
动量、每 rank 随机状态和抽样位置。全局有效 batch 为 48，每 5,000 次精确
保存；边界最后一批减小，总计 2,100 次参数更新。输入帧与监督帧计数相等，
不把多个帧误记成多次资产曝光。

保留前 5k 已执行的 20k OneCycle 学习率前缀；5k 时约为 `9.3435e-5`，之后
按连续余弦曲线下降到 100k 时的 `2e-6`。Adam beta1 也连续延伸到 0.95，
不重置优化器。原 20k 计划的完整资产顺序、T 和更新边界前缀必须精确保持。
λ=0 尚未启动，需要采用同样的 100k 总预算、分段学习率、初值和抽样序列。

两张既有 H100 顺序执行各阶段。独立监督器限制单 CPU、64 GiB RAM、每卡
85% 显存，并核对实际 GPU UUID。分配到期前预留 20 分钟保存完整状态并交接；
这种阶段结束不代表 100k 总目标完成。此次按用户明确授权的 direct-SSH 例外运行；
如实记录没有内核调度器组成员资格，不冒充原 allocation 的进程。

## 验证和评价

CPU 阶段复用未改变数据的完整静态证书，新增真实样本的父 ID 与官方坐标
往返检查、原始 bestB GT/帧身份检查、官方权重与词表扩展检查。GPU 小拟合
使用两个不同的非 52 关节资产，检查 T=2/T=24 梯度；32 次更新后要求主 CE、
结构 CE、坐标 CE 分别不高于初始的 85%、90%、95%，且每 rank 至少有一次
非容量强制的 EOS。门槛只说明基本可训练，不是泛化质量验收。

容量测试覆盖 T=6/12/24 各档位的长序列、大网格及混合样本，并保留 Adam
状态与梯度累积。正式训练每 5k 在固定 8 seen / 8 heldout / 16 valid 资产、
每资产四帧上评价；100k 另评完整 32/32/128 资产八帧面板。

报告原始连续 GT 的空间边匹配 F1、准确关节数、准确 DFS 父关系、同资产
跨帧结构完全一致率和成对一致率。失败生成 F1 计零；J2J 单独标明成功帧分母。
语法屏蔽只限制合法序列，不使用 GT 关节数、结构或坐标；容量只剩 EOS 的
结束单独标记。bestB 仅在相同资产、原始帧与 GT 上作为历史质量参照。

## 启动前测量

真实数据审计的 20 项 T=2/24 检查及 128 个参考视图均通过；最长完整目标为
训练集 1,211、验证集 1,013 tokens。实际官方词表为 267，追加 ID 后为 523；
CPU 与两张 GPU 上的初始参数指纹完全一致。

两个非 52 关节资产共同进行 32 次更新后，主 CE 分别降至初始的 51.37% 与
3.92%。53 关节样本的两帧生成完全正确，原始 F1 为 1.0；22 关节样本的两帧
都生成 130 关节，原始 F1 约 0.2311。四次生成均自然 EOS。这支持基本可训练性，
同时说明跨帧一致仍可能一致地错误，不能替代正确结构与泛化评价。

九组双卡容量测试全部通过，最高 allocated/reserved 为 34.70/35.09 GiB，
NVML 采样最高显存占用 46.48%，低于 85% 限制。正式物理 batch 使用已测的
T=2..6 每卡 12、T=7..12 每卡 6、T=13..24 每卡 3，累积到全局 48 个资产。

## 批量吞吐修复（待实测验收）

用户要求修复 batch，并明确选择保留当前两张 H100，先完成批量提速。
当前分配仍为一个 CPU slot；8 CPU 的资源变更暂缓，不自行扩大绑定范围。
已在完整 20k 断点处交接，保留全部已完成更新及模型、Adam、RNG 与采样位置。
旧代码目录冻结，新阶段在独立 `batch_code` 中执行，不覆盖运行中的代码。

候选物理 batch 为 T=2..6 每卡 24、T=7..12 每卡 12、T=13..24 每卡 6。
每次更新仍为全局 48 个资产；只改变分块，整个 100k 样本、帧、种子和更新
顺序保持完全相同。模型、损失、全部帧监督、数据、归一化、学习率与精度不变。
恢复时的参数和优化器状态要求精确一致；改变计算分块后的浮点轨迹不宣称逐位一致。

先做 CPU 完整断点恢复审计，再进行双卡容量与吞吐对照。九组长序列、大网格、
混合样本均使用完整全局 48 资产；每组执行两次更新以纳入真实 Adam 状态。
混合组另用旧物理 batch 运行同一输入，对照时固定权重（仅测试用学习率为零），
逐资产核对数据索引、原始帧、种子和完整 GT。记录准备数据、编码、解码与损失、
反传、优化器及总耗时。以第二次更新两卡的较慢耗时计算各档速度比。

沿用每卡 85% 显存和 64 GiB RAM 上限，不用降低监督或数据规模换取通过。
显存与三个参数组梯度检查通过且实测提速后才批准正式续训；若候选超限，
只允许将对应档位恢复为原已测 batch，再重新绑定证据。测试权重不用于续训。
容量测试的同步计时只用于同输入比较，不直接作为完整训练的预计完成时间。

### 时间注意力执行修复

旧 B12 两轮正常，候选 B24 前向 loss 有限但反向异常，显存约 67%，没有 OOM。
最后一层时间注意力的同输入隔离对照形状为 `[26904, 6, 1024]`；原始输入、
输出及传入梯度均有限。PyTorch 2.5.1+cu121 下，default-full 与 flash-only-full
有非有限 in-projection 和输入梯度，拆为两个 13,452 序列的调用及 math-only
均为有限。隔离对照的较慢卡耗时分别约 0.065/0.048/0.069/2.192 秒，不能
替代完整模型吞吐。没有直接跟踪 default 实际选中的后端。

大批次异常路径在反向后输出也非有限；旧探针将 NaN 与零取 max，导致它们的
forward-difference 字段错误记录为零，不得据此声称前向一致。半批和 math 的
有限输出及零差异有效；后续探针分别记录反向前后状态，原始证据不改写。

执行修复仅在显式 v2 续训配置启用：将时间层的独立序列维分块为至多 13,452，
不切分时间维，不删除 anchor、帧或监督。原模型参数名、张量、优化器与科学
配置不变；默认行为仍不分块。只对零 dropout 开启。配置固定该单一源文件
修改前后的 SHA，并继续禁止其他核心代码变化；执行策略也纳入检查点契约。
需通过 CPU 等价性、完整双卡九组容量/吞吐和最终源版本的 20k 恢复审计。
