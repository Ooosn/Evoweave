# 已知参考骨架条件下的多姿态骨骼生成技术报告

日期：2026-10-27。范围：任意拓扑骨架、参考几何条件、观测 mesh 到关节位置、跨拓扑运动生成与相关定位机制。

本报告的目标是为 Evoweave 第二阶段建立可追溯的设计依据，不是为已经实现的 OPT 方案补充理由。当前任务保持不变：第一阶段先完整解码一个真实参考姿态的骨架，完成 UniRig 的分支坐标融合；第二阶段接收这棵完整骨架和多个已观测姿态的 mesh，生成同一组关节在其他姿态下的 XYZ。主路线是学习式条件生成，不以逐资产拟合、配准或 IK 优化代替网络预测。本轮只进行技术研究和文档整理，没有修改模型或启动训练。

## 摘要与主要判断

1. **最接近我们的任务接口是 MoCapAnything V1，而不是一个通用坐标语言模型。** 它把参考骨架与参考几何转成有身份的关节表示，再从目标观测中读取定位证据。V2 的局部与全局骨架交互、参考条件注入和训练分布衔接也值得借鉴，但它的旋转阶段需要我们目前没有的额外信息。
2. **“怎样利用参考骨架”和“怎样生成输出”必须分开设计。** MoCapAnything、GraphCape、SCAPE 主要启发前一个问题；AnyTop、UniMate、TopoCap、MoMask 主要启发结构化输出表示与生成过程。把参考条件编码器接到 OPT 后面，不等于已经解决这两个问题。
3. **最值得优先深化的是几何条件化的、以每个关节为单位的连续生成器。** 一个候选是直接在 `姿态 × 关节 × XYZ` 上做条件 flow matching，另一个是先学骨骼运动表示再做潜空间生成。前者接口更直接；后者有更强的先验学习空间，但多出一个重建瓶颈和训练阶段。这里是基于任务匹配度的排序，不是效果结论。
4. **已有对应关系是我们比视频方法更强的输入，不能浪费。** 同一资产的表面 anchor 在不同姿态间有对应关系，可以把参考位置、目标位置、位移、法向和学习特征共同提供给生成器。但表面对应不等于关节对应，不能把最近表面点或 attention 权重直接当作骨骼绑定。
5. **不能照搬这些方法的隐含条件。** 典型差异包括静止姿态与任意参考姿态、关节名称、局部旋转坐标系、连续时间、骨长不变、辅助骨删除、特定骨架的动作统计，以及训练集的拓扑覆盖。它们会改变任务，而不只是改变实现细节。
6. **现有实验没有证明 AR 不适合，也没有证明冻结主干必然失败。** 它们证明当前小数据、冻结特征、条件编码和坐标 AR 的组合泛化不足。应该改变的是研究依据和验证方式，不能把失败简单归因于“用了 OPT”或“只有四层”。

## 1 我们到底要解决什么

### 1.1 输入输出与身份约束

记参考姿态为 `r`，参考骨架为 `S_r = (X_r, P)`。`X_r` 是 `J × 3` 关节坐标，`P` 是父节点数组；`J` 和树结构由第一阶段完整解码结果确定。输入还有参考 mesh `M_r` 和其他已观测姿态 `M_t`。目标是：

```text
条件 C = {X_r, P, M_r, M_1, ..., M_T}
生成 X_1, ..., X_T，每个 X_t 都有同样的 J 个关节
参考姿态保持 X_r，其他姿态只生成 XYZ，不重新生成树或关节编号
```

“同样的关节”是同一参考节点在不同姿态的位置，不是每帧独立发现一组位置近似的点。第二阶段即便输出几何形状正确，如果左右分支发生身份交换，仍然失败。反过来，第一阶段遗漏或多出的节点不会由一个固定 `J` 的第二阶段自动修正。

### 1.2 已有条件和没有的条件

| 项目 | 当前合同 | 对模型选择的影响 |
|---|---|---|
| 骨架 | 完整参考 XYZ 与父子关系；参考可来自自然预测 | 不必再学习树的生成语法，但必须保持节点身份 |
| 参考姿态 | 真实输入姿态，不保证是 T-pose 或 bind/rest pose | 不能直接把参考坐标当静止骨架变换矩阵 |
| 目标观测 | 多个姿态的完整 mesh，而非只有 RGB | 不需要重新做视频到 4D mesh 的重建前端 |
| 表面关系 | 当前采样继承跨姿态 anchor 对应 | 可显式编码变形证据；不等于已知蒙皮 |
| 关节语义 | 第一阶段没有可靠的语义名称输出 | 不能依赖 T5 编码的“左膝”等名称作为必需条件 |
| 旋转与蒙皮 | 第二阶段输入合同未提供参考旋转、局部坐标系和 GT 蒙皮 | 不能直接接需要这些量的旋转或 LBS 解码器 |
| 姿态顺序 | 随机采样的姿态集合，不保证连续或等时间间隔 | 默认不应使用固定视频窗口、速度平滑或时间顺序编码 |
| 坐标 | retained-root RT 对齐；由选定输入 mesh 联合 bbox 归一化 | 不得按 GT 骨架重新定尺度或偷偷改坐标系 |
| 标签 | 保留全部合同内关节与帧，不裁剪 GT、不删除辅助骨 | 论文的数据清理和关节裁剪不能直接搬入 |

当前数据声明为 18,002 个训练资产和 967 个验证资产，近期主干对照使用其中固定的 5,000 资产训练清单。第二阶段的 8/64 资产实验只是小规模诊断，不代表已在这个数据覆盖上验证。输入可用性以项目合同为准，不以原始文件里“可能还藏着什么字段”为准。

### 1.3 三种不同的“生成”

**一次前向的条件解码**可以同时输出全部关节；**自回归生成**按某种顺序生成离散或连续变量；**扩散/flow 生成**通过多次网络更新联合生成整个状态。三者都能用学习的条件关系，不必包含逐资产拟合。若要求显式建模条件分布，多模态生成主要由后两类承担；一次前向定位仍是有价值的机制对照，但不能冒充已经验证的概率生成器。

还要区分两种“迭代”：flow 的采样步是已训练网络的生成计算；逐资产优化则在测试时为该资产最小化一个拟合目标。采用前者不等于回到用户排除的后者。训练网络本身使用梯度优化也不属于这里排除的测试时拟合。

## 2 路线地图

本轮把 15 项工作放在同一任务坐标系下比较。核心方法核读方法章节；能取得代码的重点核对条件输入、前向路径和配置。没有将任何论文成绩表述为本地复现结果。

| 路线 | 代表工作 | 主要解决什么 | 与我们的关系 |
|---|---|---|---|
| 已知 rig 加视觉观测 | MoCapAnything V1/V2 | 参考定义关节，目标观测提供运动 | 第二阶段接口最接近 |
| 拓扑条件运动先验 | TopoCap | 先学运动表示，再由视频生成潜变量 | 潜空间生成候选，不是即插即用 |
| 任意拓扑生成 | AnyTop、UniMate | 骨架条件下的扩散或 flow | 生成器结构、图条件和掩码机制 |
| 从变形学习骨骼表示 | RigMo、Neural Marionette | 表面运动、结构与运动的联合表示 | 几何监督思想；输出骨骼定义不同 |
| 动态几何辅助 rigging | MoRig | 运动部件边界与关节、蒙皮定位 | 如何使用 anchor 运动证据 |
| 参考关键点迁移 | GraphCape、SCAPE | 从支持样例定义关键点，再定位新实例 | 身份、几何绑定、交互方式 |
| 离散运动补全 | MoMask | 双向掩码生成学习到的运动 token | AR 之外的离散生成路线 |
| 骨架间动作重定向 | Skeleton-Aware Networks | 结构化编码、共享动作表示 | 结构算子的启发，任务不等价 |
| 固定人体运动理解 | WHAM、MotionBERT、HybrIK | 几何中间表示、运动先验与旋转恢复 | 局部机制参考，不能整套移植 |

## 3 核心方法细节

### 3.1 MoCapAnything V1：参考骨架如何变成有几何依据的 query

**论文路线。** 输入 rigged reference asset 和视频。参考编码器融合关节位置、骨架关系、参考 mesh 与图像，形成每关节 query；目标端使用视觉特征和重建的 4D mesh 点特征。关节表示复制到各帧后，解码层组合图结构交互、目标视觉/几何交叉注意力以及同一关节跨帧交互，直接输出 XYZ。训练主要是带 joint mask 的位置 L1；输出旋转属于后续 IK 阶段。[论文 §3.3-3.5](https://arxiv.org/html/2512.10881v1#S3.SS3)

**实现核对。** 项目链接指向的公开仓库明确声明是 clean reimplementation。`models/v1/mesh2pose/model.py` 的 `RefQueryEncoder` 用参考坐标的位置编码初始化 query，再与参考 mesh、图像交互；`temporal_trunk.py` 在多层中重复读取目标条件，最后用共享 MLP 输出三维坐标。类名含 `DiTBlock` 不代表这个分支在做扩散：该前向没有噪声状态及扩散采样循环。[参考编码](https://github.com/phongdaot/MocapAnything/blob/c99fb22c2f6001958c73c197065322b98ca0b93b/models/v1/mesh2pose/model.py)、[目标解码](https://github.com/phongdaot/MocapAnything/blob/c99fb22c2f6001958c73c197065322b98ca0b93b/models/v1/mesh2pose/temporal_trunk.py)

**与我们的结合。** 可以保留“参考关节定义身份，目标几何决定位置”的接口，去掉我们不需要的视频重建与图像分支。目标条件应来自已观测 mesh，而不是生成一个猜测的 mesh 再定位。参考编码与生成解码应明确分工：前者建立关节语义，后者在多层中持续利用目标几何。把这种条件路径用于 flow 或掩码生成，是我们的新设计，不是论文已验证的组合。

**不能直接搬的部分。** 时间窗口、图像特征、关节名称和后续 IK 均不能成为默认依赖。公开实现还存在静态关节覆盖逻辑；我们不能从目标 GT 的时间统计推断“哪些关节静止”再在推理时强制复制参考位置。

### 3.2 MoCapAnything V2：参考条件、局部全局交互与端到端衔接

**论文路线。** 本轮读到 v4，而不是只看早期摘要。V2 把 Video-to-Pose 与 Pose-to-Rotation 接成可联合训练的两阶段网络。前者由参考位置与参考图像构造 query，直接读取视频，不再依赖预测 mesh；后者还接收 rest pose 和一个参考“位置-旋转”对。GL-GMHA 在骨架局部链路约束与全局关节交互之间交替；训练包含位置、旋转、角速度及根旋转项，并逐渐提高使用预测 pose 而非 GT pose 的比例。[论文 v4 §3](https://arxiv.org/pdf/2604.28130v4)

**技术思想。** 参考条件不只是一个全局向量，而是持续参与解码的每关节条件。后续阶段不仅要适应干净 GT，还要适应上游实际预测分布。位置与旋转分开，是因为两者依赖的信息不同，不是“两个模块就应该互不影响”。

**源码与成绩边界。** 公开代码提供图关系、图距离及可选 tree mask，也提供 GT/预测 pose 混合训练。发布说明承认公开 split 与论文不同，Zoo-Unseen 旋转误差约 19.6 度而不是论文的 6.54 度；不能把下载代码称为已复现论文。公开设置也不是论文超参数的逐项复制。[图注意力](https://github.com/phongdaot/MocapAnything/blob/c99fb22c2f6001958c73c197065322b98ca0b93b/models/v2/pose2rot/graph_attention.py)、[复现说明](https://github.com/phongdaot/MocapAnything/blob/c99fb22c2f6001958c73c197065322b98ca0b93b/RUN.md#metrics--reproduction)

**与我们的结合。** 借鉴局部/全局交互和参考条件注入；借鉴上游误差适应的训练思想。我们只要求 XYZ，没有必要为模仿 V2 而新增旋转输出。V2 去掉的是噪声较大的“预测 mesh 中间结果”，不能据此推断我们也应去掉真实观测 mesh。

**重要限制。** 参考位置-旋转对补充了旋转坐标约定，但不能被解释成“任意时刻的骨轴 twist 都由 XYZ 唯一确定”。新的 twist 仍可能依赖观测和学习先验。我们的输入没有参考旋转，也没有可靠名称，因此不能直接使用完整的 V2 旋转路径。

### 3.3 TopoCap：先学运动解码能力，再学习由观测进入这个空间

**论文路线。** 第一阶段 Graph CVAE 编码异构骨架运动，以固定数量的 latent slots 压缩关节维，保留时间维；目标 rig 的结构与 rest 几何构成解码 query。解码器先输出全局位置和朝向，再解析转换为局部旋转及弹性 offset。第二阶段用视频特征和 canonical rig embedding 条件化 flow，生成运动 latent。重建监督包含全局几何、朝向、时间项和 KL。[论文 §4](https://arxiv.org/html/2606.12153v1#S4)

**实现核对。** 已核读的公开代码在压缩后的 latent slots 上做时间注意力，不是直接对最终 XYZ 做跨帧修正；解码 query 使用 rest transform。视频生成阶段加载并冻结预训练 VAE。公开配置主要面向预测，不能仅从存在一个 loss 函数就认定完整训练配方已经可复现。[CVAE](https://github.com/czpcf/TopoCap/blob/2e28f0b061f93a9c7c33ad9c6050d10bfaf2ae30/src/model/skin_vae/autoencoders/frame_cvae_model.py)、[运动生成](https://github.com/czpcf/TopoCap/blob/2e28f0b061f93a9c7c33ad9c6050d10bfaf2ae30/src/model/motion_diffusion.py)

**与我们的结合。** 它提供一个明确的候选：先训练能在不同参考骨架下重建目标 XYZ 的条件运动自编码器，再让 mesh 条件生成器预测 latent。这样“骨骼如何合理运动”和“如何读取几何证据”可以分阶段学习，而不是同时从随机权重学习所有能力。

**代价与边界。** 必须先确认自编码器对未见资产、长链和小关节运动的重建精度。否则生成器上限已经被瓶颈限制。原模型的 rest 朝向、旋转表示和连续时间条件与我们不一致，不能只把 RGB encoder 换掉就声称兼容。论文还裁剪部分辅助骨，训练骨架限制在 2-128 关节；我们不能照搬这些数据改动。解析坐标转换与逐资产拟合不是同一件事，但本任务尚无引入其旋转转换路径的必要。

### 3.4 AnyTop：让生成器看见图，而不是只看见序号

**论文路线。** AnyTop 对 `帧 × 关节 × 特征` 做 DDPM，预测干净运动而非必须预测噪声。非根关节包含位置、6D 旋转、速度和接触信息；rest pose 作为额外时间槽，关节名称经 T5 编码。骨架 attention 利用父子、兄弟、自身、末端等关系和图距离，配合每关节时间 attention。图结构参与的是生成全过程，而不是只在输入端编码一次。[论文 §3](https://arxiv.org/html/2502.17327v1#S3)

**公开流程的关键条件。** 新骨架预处理接收该骨架的 BVH 动作文件及朝向关节；数据加载与反归一化使用各 `object_type` 的 mean/std。因此“新拓扑可生成”不能直接解释成“仅一个任意参考 pose，其他资产信息都不要”。[新骨架输入](https://github.com/Anytop2025/Anytop/blob/e780d1575ca0121f29bb53821b309cf564156a95/data_loaders/truebones/truebones_utils/process_new_skeleton.py)、[归一化实现](https://github.com/Anytop2025/Anytop/blob/e780d1575ca0121f29bb53821b309cf564156a95/data_loaders/truebones/data/dataset.py)

**与我们的结合。** 图关系和图距离是可复用的条件机制；按关节建 token 也适合保持身份。不能照搬关节名称、接触标签和每骨架动作统计。将其条件从“骨架与动作先验”扩展成“参考骨架与目标 mesh”，需要新增并验证几何交互，不是改一个条件向量就完成。

### 3.5 UniMate：直接在结构化运动空间做 flow

**论文路线。** UniMate 输入 rest skeleton 与文本，在每关节的位置、旋转、速度表示上做条件 flow matching。TADiT 结合关系/图距离 bias、基于拉普拉斯特征的 Spec-RoPE，以及由骨架池化得到的全局条件；图 attention 与时间 attention 分解执行。训练除了 flow 速度场误差，还约束重建状态的旋转与运动平滑。[论文 §3、附录 B](https://arxiv.org/html/2609.05415v1#S3)

**实现核对。** 公开 `rope.py` 提供 SignNet 式正负特征组合，处理特征向量符号翻转。发布的全数据 graph 配置使用 flow、关节名称、60 帧、最多 70 个关节，并启用增删节点等增强；它不是我们的 256 关节数据合同，也不是一组可直接继承的训练参数。[谱编码](https://github.com/Friedrich-M/UniMate/blob/b78c7807df7cf4231d4e67f8d0ece29c5e11025b/unimate/models/denoiser/rope.py)、[发布配置](https://github.com/Friedrich-M/UniMate/blob/b78c7807df7cf4231d4e67f8d0ece29c5e11025b/configs/uniml3d_60frames_graph_adaln.json)

**与我们的结合。** 相比“先压缩再生成”，它证明存在不经过 VAE 瓶颈的结构化连续生成路线。可将生成状态改成 XYZ，把文本条件换成更细粒度的参考/目标几何条件。但这意味着重新定义输入、输出和训练目标，不是现有权重直接适用。

**不应神化谱编码。** 符号不变不自动等于对重复特征值子空间任意换基不变。我们若采用谱特征，还需做节点重排、重复特征值和数值稳定性检查。图关系加参考几何已经是一条可解释的起点；没有依据要求一开始就叠齐谱编码、语义名称和全局条件。

### 3.6 RigMo：用可解释的变形表示连接 mesh 与运动

**论文路线。** RigMo 从对应顶点的 mesh 序列学习静态 rig 分支与动态 motion 分支。前者生成 Gaussian bones 和蒙皮影响，后者编码顶点位移并生成局部/全局 SE(3)；经可微 LBS 重建顶点，以顶点重建和 KL 训练。后续 Motion-DiT 在该 latent 空间生成运动，并可用观测帧作条件。[论文 §3](https://arxiv.org/html/2601.06378v1#S3)

**技术思想。** 模型的内部运动表示必须能解释表面怎么动，几何证据因此不只通过末端 XYZ loss 间接进入。它还用表面测地关系限制空间上接近、拓扑上不同的部件相互影响。

**与我们的结合。** 值得借鉴“参考形状/身份条件与动态变形证据分开编码”和“生成状态应与表面变化相容”。但 Gaussian bone 是形变控制原语，不等于我们固定参考树中的艺术家关节；好的 mesh 重建也不保证原始关节位置正确。只能作为几何约束或表示设计的参考，不能替换输出合同。

**实现成熟度。** 本次检查的项目页仍将代码标为 Coming Soon；没有将其作为已核验的可运行基线。其相邻帧位移和时间模型也不能原样用于无序姿态集合。[项目页](https://rigmo-page.github.io/)

## 4 扩展方法带来的补充与反例

### 4.1 MoRig：运动边界比最近距离更有信息

MoRig 先建立 mesh 与动态点云的对应并传播变形，再将每顶点轨迹编码成运动特征。关节候选回归、顶点相关性判断和蒙皮预测利用这些特征；邻域运动差异帮助定位运动部件边界。其后续动作迁移仍包含 IK/拟合，不能照搬为我们的主输出路径。[方法 §3.3-3.4](https://arxiv.org/html/2210.09463v1#S3.SS3)

对我们而言，对应 anchor 已经存在，重点不是重建一遍 MoRig 的对应前端，而是让关节条件读取“哪些表面区域一起动、在哪里相对运动”。手臂贴近躯干时，欧氏最近点会混淆部件；运动关系和 mesh 连通性可以提供额外证据。注意力可学习这种关系，但需要通过干预和泛化评估确认，不能仅看热图就宣称学到了蒙皮。

### 4.2 GraphCape：参考节点的编号不是稳定语义

GraphCape 将支持图像的标注关键点作为节点，先做定位提案，再以 self-attention、目标图像 cross-attention 和图 FFN 反复更新坐标。它用提案热图与多层坐标监督，并检查了关键点顺序编码：论文表 1 中，使用该编码时，打乱顺序使 PCK 从 89.26 降到 64.20；无该编码的图模型保持不变。这是其 2D 协议内的结果，不是我们的预期降幅。[方法 §3、表 1](https://arxiv.org/html/2311.17891v2#S3)

对我们的启发是让参考几何和树关系定义 joint identity，并检查合法重排后的输出。当前接口要求父节点先于子节点，诊断时应使用保持这一约束的兄弟/子树重排并同步重映射父索引，而不是输入非法顺序后把报错解释为模型缺陷。

### 4.3 SCAPE：显式匹配不是先验正确答案

SCAPE 先让支持关键点读取支持图像的全局上下文，再把关键点与目标图像特征放入联合交互。它同时更新两类特征，采用不同的 query/key 投影，直接用坐标 L1 监督，而不依赖先生成显式相似度图再修正的两阶段路径。[方法 §3.2-3.4](https://arxiv.org/html/2407.13483v1#S3.SS2)

它为“单向 joint-to-mesh 读取是否足够”提供了一个有意义的替代：骨骼和几何在下游共同更新。但不能从 2D 成功推出 3D 必胜，也不能把关节内部位置当成图像中可直接采样的像素。我们需要比较单向读取与轻量双向交互，而不是因为概念更复杂就把后者默认装进去。

### 4.4 MoMask：双向生成不等于逐坐标填 256 档

MoMask 先以 residual VQ-VAE 学习运动 token，再训练双向 masked transformer 生成基础层 token，随后预测残差量化层。推理从 mask 序列开始，反复填充和重掩码；token 表示学习到的运动片段，而不是一个 `x/y/z` 标量的均匀分箱。[方法 §3](https://arxiv.org/html/2312.00063v1#S3)

它支持“生成器不必左到右”的判断，但不能直接给我们的任意拓扑关节使用现有人体 codebook。若采用掩码路线，需要先设计保留任意关节数、图关系和几何精度的 tokenizer，并测量重建下限。另一种坐标 mask 补全是不同的新方案，不能借 MoMask 的名字跳过这个论证。

### 4.5 Skeleton-Aware Networks：静态结构与动态动作分开，但有拓扑边界

该方法使用骨架感知卷积、池化和反池化，将可约化到共同 primal skeleton 的 homeomorphic 骨架映射到共享动作空间，再在目标骨架上解码。它处理动作重定向，不读取目标 mesh 以确定动作。[论文与方法](https://deepmotionediting.github.io/retargeting)

可借的是静态 offset 与动态状态分开编码，以及沿骨架结构共享计算。不能据此认定任意不同分支数都能使用同一个池化模板，也不能为了适配模板删除我们的关节。我们的输出树已经固定，不需要重新寻找一个简化公共骨架。

### 4.6 Neural Marionette：运动发现的骨架不等于标注骨架

该方法用体素序列重建学习关键点及其连接，再通过结构化动力学模型生成运动。体积覆盖、关键点分离和轨迹关系等监督促使关键点解释动态形状；运动阶段使用骨架约束的潜变量表示。[方法 §4](https://arxiv.org/html/2202.08418v1#S4)

它说明运动重建能帮助学习紧凑结构，但也暴露我们的重要边界：仅靠可解释表面运动，通常不能唯一恢复艺术家定义的全部内部关节，尤其是静止、零蒙皮影响或冗余节点。我们有参考关节身份和 GT XYZ，就不应主动把任务降为无监督关键点发现。

### 4.7 WHAM、MotionBERT、HybrIK：借机制，不借固定人体假设

**WHAM** 先以合成投影运动学习运动编码，再融合图像特征；连续运动表示和中间 3D 关节共同服务下游。可借的是有定位监督的中间表示和分阶段预训练，而不是人体接触、相机轨迹与固定模板。[方法与训练](https://arxiv.org/html/2312.07531v2#S3)

**MotionBERT** 维护 `帧 × 关节` 表示，以不同顺序组合空间和时间交互，再融合两条分支；掩码和噪声用于预训练。可借关节级多姿态交互与鲁棒性训练，但不能把已定位的 2D 人体关节输入等同于任意 mesh 上尚待定位的内部关节。[方法 §3](https://arxiv.org/html/2210.06551v3#S3)

**HybrIK** 先定位关节，再结合参考人体模型恢复 swing，并学习补充 twist。它帮助区分位置与旋转所需的信息；其解析运动学不是我们必须引入的输出步骤，也不是任意拓扑泛化的证据。[论文](https://openaccess.thecvf.com/content/CVPR2021/html/Li_HybrIK_A_Hybrid_Analytical-Neural_Inverse_Kinematics_Solution_for_3D_Human_CVPR_2021_paper.html)

## 5 跨论文比较后可以确定的技术要点

### 5.1 条件应回答三个不同问题

**这个关节是谁？** 用参考 XYZ、父子/祖先关系、相对骨向量及参考 mesh 上下文回答。序号只提供张量索引；不同资产的第 17 个关节不具有共同语义。图结构也不是万能身份标签，对称子树仍需要参考几何及目标观测区分。

**这个关节在目标姿态应该去哪里？** 必须读取对应目标 mesh 的局部和全局证据。参考-目标 anchor 配对、形变、法向与学习特征是可用输入，不能只把多个姿态压成一个全局向量后要求小 head 猜位置。

**这些关节能否组成一致状态？** 用图结构交互、多姿态同一关节交互和生成状态的联合更新回答。这既不同于表面 anchor 跨姿态 attention，也不等于给所有关节同一个全局条件。

### 5.2 不要混淆三种对应关系

表面 anchor 的跨姿态对应，是当前数据可提供的；参考 joint 到表面区域的关联，需要模型学习；参考 joint 到各姿态输出 joint 的身份对应，由第二阶段槽位合同保持。第一个关系不能自动推导出后两个。空间邻近、同一运动部件与蒙皮权重也不是同一个量。

### 5.3 随机姿态集合需要集合交互，而不是伪造时间

同一个关节可以从所有已观测姿态中获得定位线索，顺序不应决定预测。候选结构可以沿 `J` 轴做图 attention、沿 `T` 轴做无序集合 attention。若以后引入真实时间戳，再单独研究时间编码和间隔感知速度项。不能把排序后的随机帧当作等间隔视频。

分解 attention 的核心复杂度约为 `O(TJ² + JT²)`；若所有 `TJ` token 做全注意力，则约为 `O(T²J²)`。目标 mesh 交叉注意力另有约 `O(TJN)`，`N` 是 anchor 数。这解释了分解结构的计算动机，但不证明某种分解必然有更高精度。

### 5.4 保留位置精度与可变骨长

位置、旋转、latent 和 token 是不同输出表示，不应为了模仿论文而新增无用自由度。我们当前只需要 XYZ，连续输出没有均匀量化误差，但仍可能平均掉模态或忽略条件；离散输出有可计算的量化下限，但也能表示多峰分布。

不能无条件强制参考骨长恒定。当前保留的资产可能存在非刚性残差或艺术化伸缩；若加骨向量损失，应与目标 GT 骨向量比较，而不是强制等于参考长度。不能把所有关节吸到 mesh 表面，内部关节本来就不在表面上。

### 5.5 先验与观测谁决定输出

文本到动作的目标是“合理且符合描述”；我们的目标是“与这组已观测 mesh 的姿态相符”。一个视觉上自然但不跟随目标 mesh 的动作，在本任务中是错误结果。先验只能补充观测歧义，不应取代观测。

因此不能只展示多样性、平滑性或训练 loss；也不能用 best-of-N 的 GT 筛选结果代替部署时真正选出的结果。若保留多样本，主结果应明确固定采样规则，并把 oracle best-of-N 单独标注为分析指标。

### 5.6 生成机制的取舍不能只看模型名称

| 机制 | 主要建模选择 | 额外代价 |
|---|---|---|
| 标量坐标 AR | 把联合分布按 `3J` 个坐标分解，条件包括已有坐标 | 序列化、量化与逐步调用；可使用 KV cache |
| 直接 XYZ flow | 对完整关节状态学习噪声到数据的连续路径 | 多次联合更新；需校准噪声与坐标尺度 |
| 潜空间生成 | 先用表示模型压缩，再在 latent 中生成 | 重建下限、两阶段训练和表示分布偏移 |
| 掩码 token 生成 | 用双向上下文恢复未知 token，再迭代更新 | tokenizer、掩码策略、置信度与重掩码 |

flow 的 `S` 个采样步不自动比 `3J` 次 AR 调用更快：AR 有缓存，而 flow 通常每步处理整个状态。必须测同一硬件下的实际延迟与质量曲线。训练时也不能把“一次反向传播”直接当成相同算力，输入 token 数、可训练主干和条件读取次数都可能不同。

## 6 对现有实现的逐项审视

审视对象为当前本地源码版本 `37b279a` 的第二阶段，不把旧几何拟合诊断当主路线。

| 项目 | 实际已有 | 仍缺少的依据或能力 |
|---|---|---|
| 参考条件 | 参考 XYZ、父子 offset、root 标志 | 哪些信息在未见资产上真正被使用尚未通过干预验证 |
| 图结构 | self、parent、child、sibling、other bias | 不等于 AnyTop 完整图距离机制，也未检验长链传播 |
| 几何交互 | 参考及目标 mesh cross-attention | 当前是 joint 读取固定 memory；没有下游双向更新对照 |
| 表面对应 | 参考/目标 anchor 位置、位移和法向进入条件 | 未证明学到可迁移的 joint-to-surface 关联 |
| 多姿态信息 | 上游 anchor encoder 有跨姿态信息 | 下游 joint 状态按 `B×T` 展平，未进行显式 joint 跨姿态交互 |
| 生成方式 | 4 层、256 维、256 档 XYZ 的新 OPT | 未论证逐坐标序列化优于连续或双向生成 |
| 几何读取时机 | 生成前计算每关节条件 | 生成状态变化不会重新查询 mesh 并更新空间关联 |
| 主干训练 | 使用冻结主干缓存 | 没有比较部分解冻、adapter 或独立编码器 |
| 数据覆盖 | 8 与 64 个训练资产 | 不足以判定任意拓扑条件生成的泛化上限 |

条件编码器已经包含双向图交互和几何输入，所以不能说当前系统“完全没有结构信息”。但后续 OPT 的生成位置编码、序列顺序和标量量化，是额外选择，不由这些前置机制自动证明合理。当前特征不会随生成坐标动态重读几何，也不代表网络完全不能利用几何；这是一个需要对照的架构差异，而不是已确认的唯一故障原因。

### 6.1 已有测量能说明什么

下表误差是非参考姿态的平均关节欧氏距离除以目标 mesh bbox 对角线，再乘 100%；条件为正确参考骨架，同一 32 资产验证集。

| 训练条件 | 训练误差 | 验证误差 | 解释 |
|---|---:|---:|---|
| 8 资产，800 更新 | 0.228% | 16.706% | 能拟合小训练集，泛化差 |
| 64 资产，3200 更新 | 0.304% | 5.545% | 扩大覆盖和计算量后明显改善 |
| 64 资产，6400 更新 | 0.179% | 6.954% | 训练改善但验证变差，出现过拟合 |

64 资产终点的量化 GT 下限约为 0.179%，而验证 teacher-forced 误差约为 6.984%，与自由生成接近。因此，仅以自回归滚动误差解释失败不成立；仅换采样策略也缺少依据。8 到 64 的比较同时增加了数据和更新量，不是固定算力消融。中点优于终点是同一验证集上的观察，不是独立测试确认。

已有数字不能判定：图编码不足、目标几何交互不足、冻结特征不足、数据不足或序列捷径，究竟各占多大作用。它们更不能证明“所有直接坐标模型无效”。这部分以已有分析为证据，不作新的实验结论。

## 7 与我们结合的候选设计

以下是待研究的技术路线，不是本轮实施方案。共同前提是保留完整参考骨架、任意关节数和现有数据/评分合同；不把拟合出的目标 XYZ 塞给生成器。

### 7.1 公共条件路径

```text
完整参考 XYZ + 父子树 + 参考 mesh
    -> 参考关节编码 H_ref[J, d]

各姿态对应 anchors + 显式几何 + mesh/motion 特征
    -> 逐姿态、逐 anchor 条件 G[T, N, d]

H_ref + G + 当前待生成状态
    -> 图结构交互 + joint/mesh 交互 + 同关节姿态集合交互
    -> 同一组关节的目标 XYZ
```

参考编码需要让每个 query 同时感知自身局部几何和整棵树；目标条件应保留姿态维和空间位置，不能只提供一个池化向量。anchor 特征可包含 `(p_ref, p_target, p_target-p_ref, n_ref, n_target)`，这些是观测量，不是 GT 目标关节。

当前模型已经使用了其中一些信息，因此新方案的意义不能只写成“加入参考 XYZ 和 attention”。真正要比较的是：条件在生成过程中如何被使用、关节和几何是否共同更新、不同姿态的关节状态如何交换信息。

### 7.2 路线 A：直接 XYZ 条件 flow

**状态。** 对全部非参考姿态定义连续状态 `Y ∈ R^(T×J×3)`，保持参考节点身份；树与 mesh 为条件，不是需要生成的变量。

**训练。** 令 `Y_data` 为 GT，`E` 为高斯噪声，`tau` 为生成时间而非视频时间：

```text
Y_tau = (1-tau) * E + tau * Y_data
V_target = Y_data - E
L_flow = 有效非参考关节上 mean_square(V_theta(Y_tau, tau, C) - V_target)
```

**网络。** 每个关节的 token 包含当前噪声坐标、参考身份和生成时间。每层组合关节图交互、目标几何读取及跨姿态集合交互；所有关节联合更新，不按 `x1,y1,z1,...` 排队。可比较固定 memory 的交叉注意力与轻量双向交互。mesh 编码可每个样本计算一次，状态相关查询在生成步中变化。

**推理。** 从噪声积分到坐标，参考姿态和 padding 始终固定。ODE 步数是推理预算，应以延迟/精度曲线确定，不照搬论文的 50 步。必要时可在干净状态估计上加位置或目标骨向量监督，但先保持简单损失，避免同时改太多因素。

**为什么优先研究。** 它与“已知节点，只生成位置”的接口一致，没有额外 tokenizer 或 VAE 重建瓶颈；又保留明确的概率生成过程。主要风险是条件可能被忽略、噪声尺度与几何尺度不匹配、推理多步成本，以及过强先验导致输出虽合理却不跟随观测。文献并未证明它在我们的数据上优于 AR。

### 7.3 路线 B：参考骨架条件自编码器加潜空间生成

**流程。** 先在骨架运动上训练条件 encoder/decoder，使 decoder 接收参考骨架并恢复所有目标 XYZ；再由参考及目标 mesh 条件生成 latent。这个设计借鉴 TopoCap，但输出只保留我们需要的 XYZ，参考是任意真实 pose 而非假定 rest pose。

**潜在价值。** 让解码器先学会跨拓扑的结构化坐标分布，减少 mesh 条件生成器同时学习全部输出规律的负担。可以研究固定 latent slots 与可变关节 latent 两种表示。

**先决检查。** 必须在未见资产上测重建误差、长尾关节误差和高运动姿态，确认压缩没有抹去小关节、重复节点或细微形变。固定 slots 的压缩率不能仅由常见 52 关节资产决定。自编码器训练也不得利用验证资产；外部预训练权重需核对资产重叠。

**主要风险。** 多一个训练阶段和不可逆精度损失；latent 可能并未真正分离拓扑与动作。只有在路线 A 的条件交互已合理、仍显示需要更强输出先验时，这条路线的额外成本才有充分理由。

### 7.4 路线 C：图条件掩码生成

让参考骨架定义 query，双向恢复被遮蔽的目标状态，逐轮生成而非左到右解码。它呼应此前讨论的“让完整关节表示多轮更新”，但需要解决训练与推理的掩码分布、置信度校准和全 mask 起点。

若采用学习 token，先验证任意拓扑 tokenizer 的重建质量；若直接预测连续坐标分布，就不能假装是 MoMask 的现成复用。它适合明确需要局部编辑或局部条件补全的场景，目前优先级低于接口更直接的路线 A。

### 7.5 原 AR 与一次前向解码的位置

原 AR 应作为可复用的对照，而不是因为结果不好就删掉。一次前向的图条件 XYZ 解码可用于检查条件路径是否有效，但其简化并不保证效果。若比较 AR、flow 和直接解码，应尽量共享条件编码、数据、训练访问量和评分，另行报告采样成本；否则无法知道收益来自生成机制还是条件网络与计算量变化。

### 7.6 共享主干还是独立模型

这与 AR/flow 的选择是另一条轴，不能混在一次实验里决定。

| 方案 | 优点 | 风险与必要检查 |
|---|---|---|
| 冻结共享主干，训练第二阶段 | 成本较低、第一阶段不变 | 只能验证固定表示是否可用，不能代表联合训练上限 |
| 共享主干加 adapter 或部分解冻 | 保留已有能力，同时适应关节定位 | 需检查第一阶段质量回退、显存和梯度冲突；旧冻结缓存不能用于更新主干 |
| 独立几何编码器 | 第二阶段目标独立，避免任务争用 | 计算与数据需求更高；从头训练和复制初始化是不同对照 |

从接口和工程代价看，先研究共享特征加专用关节生成网络是合理候选；但主干是否冻结不能靠方便决定。比较时应固定生成器和输入几何，至少让“是否能适应定位任务”成为被单独检验的因素，而非把多个变化合成一个输赢数字。

## 8 后续验证应该回答的问题

本节是研究建议，不是已提交的训练配置。小集合仅用于检查合同和学习是否通畅，不能再次以小集合过拟合结果作为研究终点。

### 8.1 首先验证条件是否真的有用

| 检验 | 正确操作 | 能回答什么 |
|---|---|---|
| 关节重排 | 同时重排参考坐标、父索引和输出槽位；保持当前接口的合法树序 | 是否依赖数据集序号捷径 |
| anchor 重排 | 所有姿态的坐标、法向、特征同步重排 | 是否依赖偶然采样索引 |
| 姿态集合重排 | 同时重排 mesh、参考标记和目标槽位 | 是否伪造时间顺序依赖 |
| 静态化 | 将所有观测 mesh 设为参考姿态，并重新运行上游 encoder | 是否在无形变时仍凭先验产生错误运动 |
| 目标替换 | 替换真实目标输入并重新计算相应共享特征 | 输出是否跟随目标，而非记忆原姿态 |
| 多参考一致性 | 同一观测集合下改变参考帧，统一节点身份与坐标后比较目标预测 | 是否过度依赖某个参考姿态 |
| 联合刚体变换 | 同时变换所有 mesh、骨架并沿现有规则归一化 | 是否学到了不合理的绝对方向捷径 |

静态化不能只改缓存里的位置而保留原 motion features，因为共享特征可能仍携带原目标姿态信息。删除某个条件或置零可作为压力测试，但其输入可能离开训练分布；若要因果比较一个模块的价值，还需对应的训练消融。

### 8.2 正确参考与自然预测参考必须分开

正确参考评估定位上限，使用关节身份对齐的 MPJPE、误差分位数和 PCK。自然预测参考评估完整链路，保留第一阶段失败、数量错误和结构错误，不按 GT 修补输入。PCK@5% 中的 5% 指目标 mesh bbox 对角线，是较宽松的定位阈值，不能代替连续误差。

不能直接把 V2 的 GT/预测混合训练照搬：我们的预测参考可能改变关节数与树，GT 目标没有天然的一一对应。先研究同拓扑的坐标扰动和参考姿态多样性是可控的；真正引入错误拓扑时，需要单独定义训练标签对应与未匹配节点处理。评估时逐帧最近邻距离也可能隐藏身份交换，可增加“参考帧建立一次对应、后续固定”的辅助指标，但不得把这种 GT 对应用于推理。

### 8.3 数据覆盖与公平比较

应覆盖常见模板之外的树深、分支数、关节数、重复/短骨、较大形变和静止部件。5,000 资产训练清单已经比 64 资产诊断更适合讨论泛化；具体训练预算仍须单独制定。固定按资产划分的验证集，并保留训练资产的未见原始姿态评估，区分“新资产泛化”和“同资产新姿态泛化”。

比较至少报告训练资产数、资产访问量、非参考目标访问量、更新数、训练时间和推理预算。主干是否可训练、外部预训练、归一化及参考条件必须明确。预训练来源涉及 Objaverse/UniML3D/Mobjaverse 时，需要核对资产 UID 重叠；名称相近的数据集或相同总量不表示划分兼容。

在候选已显示稳定改进后，使用多随机种子确认，并报告按资产配对的置信区间。不能用单一“显著性”或训练 loss 阈值代替实际质量判断，也不能事后只选最好的图片。

### 8.4 何时值得继续，何时需要改设计

**条件干预不通过**：优先检查信息入口、身份表示和泄漏，不先加训练轮次。**训练与验证差距大**：检查覆盖、正则化和条件捷径，不立即宣布生成范式错误。**自编码器重建已差**：先修输出表示，不再训练潜变量生成器来掩盖瓶颈。**正确参考好、预测参考差**：研究第一阶段误差传播与训练分布，而不是把两个问题混在一个平均分中。

几何控制方法可以保留为诊断参照，用于说明输入包含多少可利用信息；它们不进入生成器的主输出，也不替代条件生成路线。没有预先约定的质量门槛时，本报告不凭空提出“达到某个百分比就算解决”。

## 9 当前可以作出的设计判断与仍需验证的部分

**可以作出判断：** 第一阶段完整骨架应成为第二阶段的显式条件；第二阶段不需要重学生成拓扑；按关节维护状态比匿名全局向量更契合身份合同；目标几何应在解码过程中持续可访问；无序姿态不能照搬连续时间假设；旋转、语义名称与 rest pose 不是当前免费输入。

**有依据的优先级：** 深化 MoCapAnything 式参考条件接口，吸收图结构和多姿态交互；优先论证直接 XYZ 的连续条件生成，保留 AR 与直接解码作机制对照；把 TopoCap 式潜空间先验列为独立候选，把掩码生成列为需要先解决表示问题的候选。

**仍需实证：** 几何双向交互是否必要，joint 集合交互是否有效，共享主干应该训练哪些部分，直接 flow 是否优于 AR，latent 先验能否改善长尾而不牺牲精度。这些问题不能靠论文名称、单次小集合结果或一次训练集拟合来回答。

本次调研改变的不是“把 OPT 改名成 DiT”，而是设计顺序：先确定每个关节怎样从参考几何得到身份、怎样读取目标形变、怎样保持全局结构，再在同一条件接口上选择生成机制。

## 附录 C 术语速查

| 术语 | 本报告中的含义 |
|---|---|
| topology / rig | topology 是节点与边的关系；完整 rig 往往还包含静止变换、蒙皮和坐标约定，不能只翻译成“骨架编号” |
| rest pose / reference pose | rest 是动画绑定的基准状态；reference 只是提供条件的已知姿态，两者不必相同 |
| joint query | 每个参考关节对应的可更新特征，不是重新引入一个匿名虚拟帧 |
| cross-attention | 一组特征向另一组特征读取信息；标准形式只更新 query 一侧 |
| permutation equivariance | 合法重排输入节点并同步重排图后，输出只发生对应重排，不改变物理预测 |
| flow velocity | 噪声状态到数据状态的生成路径导数；不是角色在物理时间中的关节速度 |
| latent / KL | latent 是学习到的压缩表示；KL 用于约束潜变量分布，不直接保证 XYZ 准确 |
| 6D rotation | 用两个三维向量构造正交旋转基的连续表示，不是额外六个空间位置 |
| FK / IK | FK 从骨架与局部运动算位置；IK 从目标几何推运动参数，可解析、学习或数值优化，不能一概等同 |
| adapter / partial finetuning | adapter 是附加的小型可训练模块；部分微调只更新主干的一部分权重 |
| teacher forcing | 预测当前变量时使用真实前缀；自由生成只能使用模型自己已经生成的内容 |
| normalized MPJPE | 平均关节位置误差再除以目标 mesh 对角线；不同于训练输入使用的联合 mesh bbox 归一化 |
